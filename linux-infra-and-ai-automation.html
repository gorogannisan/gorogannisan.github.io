Как выпускать цифровые продукты со скоростью целой команды разработчиков? Мой практический опыт развертывания легковесной Linux-инфраструктуры, настройки воспроизводимых CI/CD пайплайнов и бесшовной интеграции терминальных AI-ассистентов в повседневный рабочий процесс.

  1. 01 Git Push Отправка изменений ветки в локальный Git-репозиторий
  2. 02 Self-hosted Runner Мгновенный запуск линтеров и тестов в локальном Docker
  3. 03 AI Diff Review Проверка изменений и генерация release notes через CLI-модель

Зачем независимой разработке свой DevOps

В сольной разработке или небольшой команде любая ручная рутина — сборка APK, ручной перенос файлов по FTP, генерация сертификатов LetsEncrypt или ручное редактирование конфигов Nginx — напрямую убивает время, которое должно идти на разработку продуктовых фич.

Мой фундаментальный принцип: если действие повторяется больше двух раз, оно обязано быть автоматизировано скриптом. Никаких ручных кликов по серверам в терминале.

Архитектура: Self-hosted Git, воркеры и изоляция

Вместо перегруженных облачных решений с высокими тарифами я использую легковесный стек на базе выделенного Linux-сервера:

Linux Host Ubuntu LTS Server
  1. Gitea & Local Runners Собственный Git-сервер и воркеры с нулевой сетевой задержкой
  2. Claude & Gemini CLI Integration Терминальные агенты для ревью коммитов, тестов и документации
  3. Caddy Reverse Proxy Автоматический выпуск и продление SSL-сертификатов без cron
  4. Docker Network Isolation Изолированные сети контейнеров без доступа наружу

Интеграция терминальных AI-агентов в воркфлоу

Я использую официальные CLI-инструменты моделей (Claude Code и Gemini CLI) прямо из терминала Bash, встраивая их в pre-commit хуки и CI-пайплайны.

Автоматический ревью diff перед коммитом

Скрипт читает несинхронизированные изменения в рабочей ветке, формирует краткое резюме и проверяет соблюдение архитектурных соглашений:

ai-review.sh 
#!/usr/bin/env bash
set -euo pipefail



# Извлекаем diff текущего стейджинга
DIFF=$(git diff --cached)



if [ -z "$DIFF" ]; then
    echo "Нет изменений для анализа."
    exit 0
fi



# Отправляем diff в CLI модель для проверки безопасности и конвенций
echo "$DIFF" | gemini -p "
Ты старший системный архитектор. Проанализируй этот Git diff.
1. Найди утечки API ключей или паролей.
2. Проверь обработку исключений и утечки ресурсов.
3. Предложи лаконичный conventional commit message.
"

Безопасность: SSH-ключи с аппаратными токенами

Все боевые серверы защищены по строгим стандартам промышленной безопасности:

  1. Отключение парольного доступа. В /etc/ssh/sshd_config отключен вход по паролю (PasswordAuthentication no) и запрещен прямой вход от root.
  2. Ключи FIDO2 / ed25519-sk. Доступ к боевым серверам разрешен исключительно по криптографическим ключам с физическим подтверждением нажатием на токен. Украсть такой ключ из файловой системы невозможно.
  3. Fail2ban и UFW. Фаервол держит открытыми только 80, 443 и нестандартный SSH-порт. Любые попытки перебора блокируются на уровне ядра Linux.
